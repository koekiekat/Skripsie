\mychapter{Dataset}{Dataset}{}\label{chap:dataset}

\mysection{Background}{Background}\label{sec:background}

The dataset used contains three 72-hour recordings, recorded in False Bay, near Gordon's Bay, between 22 April 2023 and 22 June 2023.
The recordings were taken at a depth of 20 to 30 metres at the coordinates S 34.17$^\circ$, E 18.76$^\circ$.

The device used for the recordings was a single omnidirectional hydrophone, designed and built by a research group in the
Department of Electrical and Electronic Engineering at Stellenbosch University.

The recorded data has a sampling rate of 8 kHz and a 16-bit resolution. The data was extracted as a 72-hour \ac{WAV} file from a \ac{SD} card
used by the recording device~\cite{data_set}.

\mysection{Labelling}{Labelling}\label{sec:labeling}

Detection tables, containing the start and end times of calls within each of the three files, were provided by a previous research
project that used a band-limited energy detector to flag calls. This method unfortunately did not detect all the calls within the
audio files, and none of the calls were labelled as a specific call type~\cite{data_set}.

Another detection table was obtained from Tonitz et al.~\cite{gunther_calls}, which contained more detections for the first 72-hour file and call labels for
all three files.
This meant that, while all three files contained labelled calls, only one contained enough labelled calls to use the entire file
without expecting an excessive number of unlabelled calls.

\mysection{Data Splitting}{Data Splitting}\label{sec:data-splitting}

For this project the data was split into three sections: template data, hyperparameter tuning data and evaluation data. Each of the
72-hour audio files was assigned to a different section. Given that only
the first of the three 72-hour audio files was well labelled, it was decided that this file would be used as the evaluation data.
The second audio file was used for hyperparameter tuning and the third was used to select templates. Labelled calls for the
tonal downsweep call type were only found in the audio file used for evaluation. Therefore, due to a lack of data, this call type was ignored.

\mysubsection{Template Selection}{Template Selection}\label{sec:temp_sel}

The audio file recorded starting on 29 April 2023 was used to select templates. These templates were
used as the baseline for \acs{DTW} comparisons.

For the three considered call types (single-tones, multi-tones and burst-tonals), the maximum number of templates per call
type that could be
extracted, such that each call type had the same number of templates, was 10. The limiting call type was burst-tonals.
In Table~\ref{tab:dataset_counts} it can be seen that there were 11 available burst-tonals. However, it was decided to make 10 the maximum
number of templates per call type.

To ensure that the 10 templates chosen were representative of varying \acs{SNR} values, templates were
chosen by looking at spectrograms
of labelled calls throughout the audio file. The visual inspection was also necessary
since some of the calls labelled as single-tones looked more like
multi-tones and some of the multi-tones could actually be classified as burst-tonals. This overlap in
possible classification
was due to the variety of human labellers and the common frequency components between call types.

\mysubsection{Hyperparameter Tuning Template Selection}{Hyperparameter Tuning Template Selection}\label{sec:tune_temp_sel}

The audio file recorded starting on 26 April 2023 was used to select templates used for hyperparameter
tuning, referred to as calibration templates. These calibration templates were used to determine the \acs{DTW} cost threshold below which a
segment of audio could be considered a call. For the call type calibration templates, 10 templates were chosen for each call type. This was
again limited by the maximum number of burst-tonal templates. In this file there were only 9 labelled burst-tonals. However, when selecting
multi-tone templates, one call originally labelled as a multi-tone was judged,
based on its spectrogram, to be a burst-tonal. This call was relabelled and used
as the tenth burst-tonal template, so that each call type had 10 call type calibration
templates. The call counts in Table~\ref{tab:dataset_counts} reflect the
original labels, before this change.

Besides these 30 call type calibration templates (10 for each call type), 100 background calibration templates were also selected.
Within each audio file, most of the time was made up of background
noise and only some parts actually contained calls.
This was simulated by selecting many more background calibration templates than call type calibration templates. Since there
is no table
labelling background noise, background calibration templates of varying sizes were extracted from the file and 100 templates
were manually selected. The reason for the manual selection process
is linked to the unreliability of the labelled data. The audio file used for selection of calibration templates was only labelled by
the band-limited energy detector and thus did not label all the calls
within the file. This means that some of the samples extracted as background audio actually contained calls that had never been labelled.
Manually selecting each template
ensured that all the templates chosen contained only background noise.

\mysubsection{Evaluation Data Selection}{Evaluation Data Selection}\label{sec:eval_dat_sel}

The audio file recorded starting on 22 April 2023 was used for the final evaluation of the whale
call detection model. No templates were extracted; instead, the entire file was swept to search for calls.

As seen in Table~\ref{tab:dataset_counts}, this file was the only file that contained tonal downsweep calls. Due to the limited number of these
calls, all the labelled tonal downsweeps within this file
were ignored while testing.
